## 문제 정의 (Problem Statement)

우리 팀(2인: 모델 담당 고용민, 인프라 담당 차가원)은 "고정된 ModernBERT-base의 여러 층 표현을 어떻게 결합하느냐에 따라 분류 오차율이 얼마나 달라지는가, 그리고 그 효과가 데이터 양·백본 학습 여부·과제·입력 길이에 따라 어떻게 달라지는가"라는 연구 질문에 12/14 최종 발표까지 답해야 한다.

평가의 55%가 방법론(실험 설계의 엄밀성 30% + 결과 분석과 해석 25%)이고, PDF는 변인 통제·반복 실험·동일 튜닝 예산·오차율/파라미터 수/학습 시간 동시 보고·"차이 < 표준편차면 효과 없음"을 요구한다. 지금은 코드가 없고, 설계 결정(ADR 0001~0009)만 있다. 이 결정들을 지키지 않는 코드가 결과표에 섞이면 다음 같은 문제가 생긴다.

- 결합 방식마다 튜닝 예산·표본·시드가 달라져 비교가 불공정해진다.
- 층 출력 척도 차이(pre-norm, 마지막 값만 최종 정규화) 때문에 **층 가중치**가 "값이 커서" 커진 것을 "정보가 유용해서"로 잘못 해석한다.
- 여러 실행이 한 GPU를 나눠 써서 **학습 시간**을 설정끼리 비교할 수 없다.
- **디버깅 실행**이나 **재현 트랙** 수치가 본 실험 결과표에 섞인다.
- 결과를 본 뒤 판정 기준을 바꿨다는 의심을 받는다.
- 층 벡터 캐시가 다른 설정(길이·자르기·버전)으로 만들어졌는데 모르고 재사용한다.

## 해결 (Solution)

하나의 실험 파이프라인을 만든다. 사용자는 **실행 설정**(데이터셋, **데이터 양 조건**, **결합 방식**, 백본 조건, **입력 설정**, 시드, 학습률)을 고르면, 파이프라인이 ADR의 통제 규칙을 지킨 채로 **결과 레코드**를 만든다. 결과 레코드들은 **판정 규칙 문서**와 함께 판정 모듈에 들어가 가설별 판정표(지지 / **효과 없음**)와 보고서용 표·그림을 만든다.

- **백본 고정 조건**이 기본이다. **층 벡터**를 한 번만 추출해 캐시하고, 결합 방식과 분류기만 학습한다(ADR 0004).
- **파인튜닝 조건**은 MNLI 핵심 비교(B0 vs 가장 좋은 결합 방식)에만 쓴다(ADR 0004).
- **재현 트랙**(논문 공개 정확도 MNLI 89.1, SST-2 96.0 — 오차율로는 10.9%, 4.0%)은 별도 실행 묶음이며 본 실험 결과와 섞지 않는다(ADR 0004).
- **본 실험 실행**은 인프라 담당 한 사람이 대기열로 한 번에 하나씩 돌린다. **디버깅 실행**은 각자 동시에 돌려도 되지만 결과표에 들어가지 않는다(ADR 0009).
- 판정 기준은 11/30에 판정 규칙 문서로 고정하고, 결과를 본 뒤에는 바꾸지 않는다(ADR 0007).

## 사용자 스토리 (User Stories)

행위자: **모델 담당**(결합 방식·분류기·분석), **인프라 담당**(서버·대기열·캐시·실행), **팀**(두 사람 모두), **평가자**(교수님·보고서 독자).

### 데이터 준비

1. 모델 담당으로서, MNLI·SST-2·IMDB를 같은 방식으로 불러오고 싶다. 그래야 데이터셋마다 다른 전처리 실수가 생기지 않는다.
2. 모델 담당으로서, MNLI의 두 문장을 [SEP]으로 이어 붙인 **하나의 입력**으로 넣고 싶다. 그래야 ADR 0001대로 SST-2와 결합 구조가 같아지고 GLUE 공개 수치와 비교할 수 있다.
3. 모델 담당으로서, 학습셋의 10%를 **튜닝 분할**로 떼어 학습률을 고르고 조기 종료 시점을 정하는 데에만 쓰고 싶다. 그래야 학습률을 고를 때 **평가셋**을 보지 않는다.
4. 모델 담당으로서, MNLI·SST-2는 공개 validation을, IMDB는 test를 **평가셋**으로 쓰고 싶다. 그래야 GLUE 테스트 정답이 비공개인 문제를 피하고 논문 수치와 조건이 같아진다.
5. 모델 담당으로서, MNLI 평가셋을 **matched 평가셋**과 **mismatched 평가셋**으로 나눠 따로 오차율을 받고 싶다. 그래야 추가 학습 없이 H4′를 판정할 수 있다.
6. 모델 담당으로서, **데이터 양 조건** "소량"을 고르면 클래스당 1,000건만 쓰게 하고 싶다. 그래야 H2를 같은 파이프라인으로 검증할 수 있다.
7. 모델 담당으로서, 소량 표본이 시드마다 새로 뽑히되 같은 시드 안에서는 모든 결합 방식이 같은 표본을 쓰게 하고 싶다. 그래야 ADR 0007의 공정 비교 규칙을 지킨다.
8. 모델 담당으로서, 소량 표본에 뽑힌 문서 ID 목록을 결과와 함께 남기고 싶다. 그래야 "같은 시드 안에서 같은 표본이었다"를 보일 수 있다.
9. 모델 담당으로서, 모든 문서에 문서 ID를 붙이고 싶다. 그래야 캐시·예측값·McNemar 짝짓기가 문서 단위로 맞춰진다.
10. 인프라 담당으로서, 교수님이 SST-2를 승인하지 않으면 SST-2를 설정에서 빼기만 하면 되게 하고 싶다. 그래야 나머지 실험 계획이 흔들리지 않는다.
11. 인프라 담당으로서, MNLI가 거절되면 AG News로 바꿀 수 있게 하고 싶다. 그래야 ADR 0003의 비상 계획을 따를 수 있다.

### 입력 길이 (IMDB)

12. 모델 담당으로서, IMDB에 **입력 설정** L128 / L512 / Lfull 중 하나를 고르고 싶다. 그래야 ADR 0006의 길이 비교를 할 수 있다.
13. 모델 담당으로서, L128은 **앞+뒤 자르기**로 앞 32 + 뒤 94 토큰, L512는 앞 128 + 뒤 382 토큰을 남기고, 특수 토큰을 포함해 각각 128 / 512가 되게 하고 싶다. 그래야 세 설정의 차이가 길이 하나로 한정된다.
14. 모델 담당으로서, **Lfull**에서는 상한까지 자르지 않고 문서 전체를 넣고 싶다. 그래야 긴 입력의 효과(H5a)를 L512와 비교할 수 있다.
15. 인프라 담당으로서, IMDB 전체를 ModernBERT 토크나이저로 세어 최대 길이를 알고 싶다. 그래야 Lfull 상한(4,096 이하면 자르지 않음, 넘으면 4,096 유지)을 정할 수 있다.
16. 모델 담당으로서, Lfull 상한 때문에 잘린 문서가 있으면 그 비율을 받고 싶다. 그래야 보고서에 적을 수 있다.
17. 모델 담당으로서, 모든 IMDB 문서에 토큰 길이와 **길이 구간**(≤512 / 512~1,024 / 1,024 초과)을 붙이고 싶다. 그래야 L512 vs Lfull을 길이 구간별로 보고할 수 있다.
18. 모델 담당으로서, 문서별 **시야 비율**을 계산해 길이 구간별로 제시받고 싶다. 그래야 시야 비율을 숫자 하나가 아닌 구간별로 보고할 수 있다.
19. 모델 담당으로서, L128의 평균 시야 비율을 확인하고 싶다. 그래야 보고서의 "지역 층이 입력 대부분(평균 약 75%)을 보는 대조군" 표현이 근거를 갖는다.
20. 평가자로서, 길이 구간마다 문서 수를 함께 보고 싶다. 그래야 최소 표본 기준과 견주어 결론을 얼마나 믿을지 판단할 수 있다.

### 층 벡터 추출과 캐시

21. 인프라 담당으로서, 층 벡터를 한 번만 추출해 캐시하고 싶다. 그래야 백본 고정 조건의 시드 반복이 값싸다.
22. 모델 담당으로서, 입력 하나당 **층 벡터** 23개(**임베딩 벡터** 1개 + 22개 층)를 받고 싶다. 그래야 모든 결합 방식이 같은 재료를 쓴다.
23. 모델 담당으로서, 층 벡터를 패딩을 뺀 토큰 평균으로 만들고 싶다. 그래야 배치 안의 패딩 양이 벡터에 섞이지 않는다.
24. 모델 담당으로서, 고정한 transformers 버전에서 23번째 층 벡터가 최종 정규화를 거친 **마지막 층 벡터**인지 1주차에 확인받고 싶다. 그래야 ADR 0005의 전제가 실제 버전에서 맞는지 알 수 있다.
25. 인프라 담당으로서, 캐시 파일에 생성 설정(모델, 버전, 길이, 자르기 방식)을 기록하고 싶다. 그래야 어떤 설정으로 만든 캐시인지 알 수 있다.
26. 인프라 담당으로서, 실행 설정과 캐시 생성 설정이 다르면 실행이 오류로 멈추게 하고 싶다. 그래야 다른 설정의 캐시를 모르고 재사용하는 사고를 막는다.
27. 모델 담당으로서, 캐시 형태가 [문서 수, 23, 768]이고 문서 ID·라벨 순서가 원본 데이터와 일치하는지 확인받고 싶다. 그래야 예측값과 정답이 어긋나지 않는다.

### 층별 정규화와 결합 방식

28. 모델 담당으로서, 모든 결합 방식·모든 데이터에서 결합 전에 **층별 정규화**(학습 파라미터 없는 LayerNorm)를 적용하고 싶다. 그래야 층 가중치가 척도 때문에 왜곡되지 않는다.
29. 모델 담당으로서, **B0**를 고르면 **마지막 층 벡터**(백본 안에서 최종 정규화된 토큰 출력을 패딩 제외 토큰 평균한 벡터)만 층별 정규화 후 선형 분류기에 넣고 싶다. 그래야 기준선이 ADR 0004·0005의 정의와 같다.
30. 모델 담당으로서, **F1**을 고르면 모든 층 벡터를 같은 비중으로 평균하고 싶다. 그래야 학습 가중치 없이 **섞기 효과**를 볼 수 있다.
31. 모델 담당으로서, **F2**를 고르면 층마다 가중치 하나를 데이터셋 전체에 대해 학습해 가중합하고, 전체 스케일 계수 γ는 두지 않고 싶다. 그래야 ADR 0005를 지키고 **가중치 학습 효과**를 분리할 수 있다.
32. 모델 담당으로서, **F3**를 고르면 마지막 4개 층의 층 벡터를 이어붙이고 싶다.
33. 모델 담당으로서, **F4**를 고르면 입력마다 층 가중치가 달라지는 결합을 학습하고 싶다. 그래야 입력별로 기대는 층이 달라지는지 볼 수 있다.
34. 모델 담당으로서, **B0+**를 고르면 마지막 층 벡터만 쓰는 2층 MLP(은닉 크기 MNLI 26)를 학습하고 싶다. 그래야 "파라미터가 많아서 이겼다"는 반론에 답할 수 있다.
35. 모델 담당으로서, 결합 방식별 학습 파라미터 수를 결과에 넣고 싶다. 그래야 결과표 옆에 파라미터 수 표를 붙일 수 있다(ADR 0008).
36. 모델 담당으로서, B0+와 F4의 학습 파라미터 수가 맞춰져 있는지 확인받고 싶다. 그래야 대조군이 설계 의도대로 만들어졌음을 보장한다.
37. 모델 담당으로서, F2를 **전역 층** 8개만 / **지역 층** 14개만으로 학습하는 ablation을 하고 싶다(임베딩 벡터는 양쪽에서 제외). 그래야 H5c를 보조 확인할 수 있다.
38. 모델 담당으로서, 층 번호별 전역/지역 여부와 **층 범위**(하위 1~7, 중간 8~15, 상위 16~22)를 한 곳에서 정의하고 싶다. 그래야 ablation과 해석이 같은 정의를 쓴다.

### 학습과 튜닝 예산

39. 모델 담당으로서, 모든 결합 방식에 학습률 후보 3개·같은 에폭 수·같은 조기 종료 기준을 쓰게 하고 싶다. 그래야 "한쪽만 많이 튜닝"했다는 지적을 피한다.
40. 모델 담당으로서, 튜닝 분할에서 고른 학습률로 시드를 반복하고 싶다. 그래야 평가셋을 튜닝에 쓰지 않는다.
41. 모델 담당으로서, 학습률 선택 결과를 남기고 싶다. 그래야 튜닝 예산이 같았음을 보고서에 보일 수 있다.
42. 모델 담당으로서, 학습 곡선을 그릴 수 있게 학습 중 지표를 기록하고 싶다. 그래야 PDF가 요구하는 학습 곡선을 보고할 수 있다.
43. 모델 담당으로서, 핵심 비교는 5시드, 나머지는 3시드로 돌리고 싶다. 그래야 ADR 0007의 반복 규칙을 지킨다.

### 파인튜닝 조건과 재현 트랙

44. 모델 담당으로서, MNLI에서 B0와 가장 좋은 결합 방식을 **파인튜닝 조건**으로도 돌리고 싶다. 그래야 H3를 판정하고 파인튜닝 대비 향상폭을 보일 수 있다.
45. 인프라 담당으로서, **재현 트랙**을 논문 설정 그대로(전체 데이터 파인튜닝, 3회) 돌리고 싶다. 그래야 논문 공개 수치(정확도 MNLI 89.1 / SST-2 96.0, 오차율 10.9% / 4.0%)와 우리 재현 수치를 비교할 수 있다.
46. 평가자로서, 재현 트랙 결과를 본 실험 결과와 따로 보고 싶다. 그래야 논문 분류 헤드 결과와 B0(층별 정규화 + 선형 분류기)가 섞이지 않는다.

### 실행 관리

47. 인프라 담당으로서, 본 실험 실행을 대기열로 한 번에 하나씩 돌리고 싶다. 그래야 학습 시간을 설정끼리 비교할 수 있고, 연구실 공용 서버에서 다른 작업과 겹치지 않는다.
48. 인프라 담당으로서, 본 실험 실행과 디버깅 실행을 구분해 기록하고 싶다. 그래야 디버깅 결과가 결과표에 들어가지 않는다.
49. 팀으로서, 디버깅 실행은 각자 계정에서 동시에 돌리고 싶다. 그래야 개발 속도가 떨어지지 않는다.
50. 인프라 담당으로서, 본 실험 실행에 사용한 transformers 버전·어텐션 구현·컴파일 설정을 결과에 남기고 싶다. 그래야 ADR 0005의 고정이 지켜졌음을 보일 수 있다.
51. 팀으로서, 일정이 밀리면 MNLI > SST-2 > IMDB 순으로 실행 우선순위를 주고 싶다. 그래야 1~4순위 가설(MNLI)이 먼저 지켜진다.

### 결과 레코드

52. 모델 담당으로서, 실행 하나가 끝나면 결과 레코드 하나(실행 설정, 평가셋 오차율, 문서별 예측값, 학습 파라미터 수, 학습 시간, 학습 곡선, 학습률 선택 결과, 층 가중치, 실행 종류)를 받고 싶다. 그래야 분석을 결과 레코드만으로 할 수 있다.
53. 모델 담당으로서, 결과 레코드에 문서 ID별 예측과 정답을 남기고 싶다. 그래야 McNemar 검정과 길이 구간별 오차율을 계산할 수 있다.
54. 모델 담당으로서, F2 실행에서는 층 가중치를, F4 실행에서는 문서별 층 가중치를 결과 레코드에 남기고 싶다. 그래야 무게중심·전역 층 가중치 비율을 계산할 수 있다.

### 판정과 분석

55. 팀으로서, 11/30에 판정 규칙 문서(판정 기준, 최소 표본 기준, 시드 일관성 기준값)를 고정하고 싶다. 그래야 결과를 본 뒤 기준을 바꿨다는 의심을 받지 않는다.
56. 모델 담당으로서, 판정 모듈이 고정된 판정 규칙 문서를 읽어 판정하게 하고 싶다. 그래야 판정 기준이 코드 안에 따로 흩어지지 않는다.
57. 모델 담당으로서, 두 설정의 오차율 차이가 시드 간 표준편차보다 작거나 McNemar 검정이 유의하지 않으면 "효과 없음"으로 판정받고 싶다. 그래야 PDF 해석 원칙과 ADR 0007을 함께 지킨다.
58. 모델 담당으로서, McNemar 검정을 같은 문서끼리 짝지어 계산하고 싶다. 그래야 평가셋이 작아서 생기는 흔들림도 반영된다.
59. 모델 담당으로서, **확증 가설**(H1, H3, H2, H4′, H5b, H5a)은 "지지 / 효과 없음"으로, **탐색적 가설**(H4, H5c)은 판정 없이 경향만 받고 싶다. 그래야 가설 성격이 결과표에서 섞이지 않는다.
60. 모델 담당으로서, H1(백본 고정 시 층 결합이 B0보다 낫다, MNLI) 판정을 받고 싶다. 그래야 연구 질문의 본체에 답할 수 있다.
61. 모델 담당으로서, H3(파인튜닝하면 결합 효과가 줄거나 사라진다, MNLI) 판정과 파인튜닝 대비 향상폭을 받고 싶다.
62. 모델 담당으로서, H2(소량 데이터에서 효과가 더 크다, MNLI) 판정을 받고 싶다. 그래야 "언제 효과가 있나"에 답할 수 있다.
63. 모델 담당으로서, H4′(처음 보는 장르에서도 유지된다, MNLI mismatched) 판정을 받고 싶다.
64. 모델 담당으로서, H5a(긴 입력 자체의 효과)와 H5b(긴 입력의 이득이 층 결합에서 더 크다, F2로 판정하고 F1은 보조) 판정을 L512 vs Lfull 길이 구간별로 받고 싶다.
65. 모델 담당으로서, H5b를 섞기 효과(F1 − B0)와 가중치 학습 효과(F2 − F1)로 나눠 보고받고 싶다. 그래야 이득이 어디서 오는지 설명할 수 있다.
66. 모델 담당으로서, ≤512 길이 구간에서 L512와 Lfull 결과가 같은지 확인받고 싶다. 그래야 파이프라인이 정상 작동함을 보일 수 있다.
67. 모델 담당으로서, 길이 구간별 결과에 최소 표본 기준을 적용받고 싶다. 그래야 표본이 적은 구간에서 과한 결론을 내리지 않는다.
68. 모델 담당으로서, 층 가중치로 **무게중심**과 **전역 층 가중치 비율**을 계산받고 싶다. 그래야 H4·H5c를 층 가중치로 볼 수 있다.
69. 모델 담당으로서, 층 가중치를 해석하기 전에 **시드 일관성**(시드 간 순위 상관, 무게중심의 시드 간 표준편차)을 검사받고, 기준에 못 미치면 해석을 보류하고 싶다.
70. 모델 담당으로서, H4(탐색적)는 MNLI와 SST-2의 층 가중치(무게중심) 경향으로 비교하고, SST-2 오차율 비교에는 McNemar 검정을 쓰고 싶다. 그래야 SST-2 평가셋(872건)의 흔들림에 휘둘리지 않는다.
71. 모델 담당으로서, 전역 층만 / 지역 층만 F2 ablation의 결과를 입력 설정별로 받고 싶다. 그래야 H5c를 보조 확인할 수 있다.
72. 모델 담당으로서, Lfull F4에서 문서 길이와 문서별 전역 층 가중치 비율의 순위 상관을 전체·라벨별로 받고 싶다. 그래야 "게이트가 길이에 반응한다"까지 말할 수 있다.
73. 평가자로서, 결합 방식별 "오차율 평균 ± 표준편차 / 파라미터 수 / 학습 시간" 결과표를 보고 싶다. 그래야 PDF의 결과 보고 형식이 충족된다.
74. 평가자로서, 표·그래프·해석 세 가지가 짝지어진 보고를 보고 싶다. 그래야 PDF의 "기본 보고" 요건이 충족된다.
75. 평가자로서, 보고서 한계 절에 B0+의 형태 차이, 전역/지역 층 수 차이(8 vs 14) 가정, 지역 층이 전역 층 출력을 입력으로 받는다는 점, 선행연구와의 비교가 정성 비교라는 점을 보고 싶다. 그래야 결론의 범위를 정확히 이해한다.

## 구현 결정 (Implementation Decisions)

### 모듈 구성

바깥 경계는 **실행 seam**과 **판정 seam** 두 개로 둔다(팀 확인).

1. **데이터 모듈** — 데이터셋과 분할을 받아 (문서 ID, 입력 텍스트, 라벨) 목록을 돌려준다. MNLI는 장르(matched/mismatched)도 낸다. 튜닝 분할(학습셋의 10%) 떼기와 소량 표본 추출(시드마다 새로 뽑고, 같은 시드 안에서는 모든 결합 방식이 같은 표본)을 맡는다.
2. **입력 구성 모듈** — 문서와 입력 설정을 받아 토큰 ID를 돌려준다. MNLI는 두 문장을 [SEP]으로 이은 하나의 입력. IMDB는 앞+뒤 자르기(L128: 32+94, L512: 128+382, 특수 토큰 포함 128/512)와 Lfull 상한을 적용하고, 토큰 길이와 길이 구간을 함께 낸다.
3. **층 구조 정의** — 층 번호(임베딩 벡터 + 1~22층)별 전역/지역 여부와 층 범위를 한 곳에서 정의한다. 전역 층은 첫 층과 마지막 층을 포함해 3층마다 하나(1, 4, 7, 10, 13, 16, 19, 22층)인 8개, 나머지 14개는 지역 층이다.
4. **층 벡터 추출기** — 입력마다 층 벡터 23개를 패딩 제외 토큰 평균으로 만들어 캐시에 쓴다. 마지막 값은 최종 정규화된 출력이다(ADR 0005, 1주차 재확인). 캐시는 [문서 수, 23, 768] + 문서 ID·라벨 순서 + 생성 설정(모델, 버전, 길이, 자르기 방식)으로 이루어진다.
5. **층 벡터 공급원(인터페이스)** — 실행 모듈이 층 벡터를 받는 통로. 캐시 공급원(백본 고정), 백본 공급원(파인튜닝), 테스트용 가짜 공급원을 주입할 수 있다. 공급원의 생성 설정이 실행 설정과 다르면 오류를 낸다.
6. **결합 헤드** — 층 벡터를 받아 층별 정규화 → 결합 방식 → 분류기 순으로 로짓을 낸다. 처리 순서는 (백본 안) 마지막 층 토큰 출력에 최종 정규화 → 층마다 패딩 제외 토큰 평균으로 층 벡터 생성 → 층 벡터 단위로 층별 정규화다. 따라서 B0에서도 최종 정규화와 층별 정규화는 서로 다른 단계다.
   - B0: 마지막 층 벡터 → 선형 분류기
   - F1: 모든 층 벡터의 단순 평균 → 분류기
   - F2: 층마다 가중치 하나(데이터셋 전체에 하나의 묶음, softmax로 정규화) 가중합 → 분류기. 전체 스케일 계수 γ 없음. 전역 층만 / 지역 층만(임베딩 벡터 제외) 옵션
   - F3: 마지막 4개 층(19~22층) 층 벡터 이어붙이기 → 분류기
   - F4: 입력마다 달라지는 층 가중치로 가중합 → 분류기. 게이트는 층별 정규화된 23개 층 벡터의 평균을 입력으로 받는 `Linear(768 → 23)`이고, softmax로 문서별 층 가중치(양수, 합 1)를 만든다(결정, "결정 필요 사항" 참고)
   - B0+: 마지막 층 벡터 → 2층 MLP(ReLU, 은닉 MNLI 26). ADR 0008의 "2클래스 25"는 B0+가 MNLI에서만 쓰이므로 현재 범위에서는 쓰이지 않는다(헤드는 ADR 0008의 두 값을 모두 정의해 두지만 본 실험은 MNLI에만 둔다)
   - F2·F4의 층 가중치를 외부로 노출한다. F2는 데이터셋 단위 가중치(`extract_layer_weights`), F4는 문서별 가중치(`extract_document_layer_weights`, `[문서 수, 23]`)이다. F4 문서별 가중치를 결과 레코드(`PredictionRecord.layer_weights`)에 채우는 일은 실행 모듈의 몫이다(T-08h 전 필요)
7. **실행 모듈 (실행 seam)** — `실행 설정 + 층 벡터 공급원 → 결과 레코드`. 학습률 후보 3개를 튜닝 분할로 평가해 하나를 고르고, 모든 결합 방식에 같은 에폭 수·같은 조기 종료 기준으로 학습한 뒤 평가셋에서 예측한다.
8. **재현 트랙 실행기** — 논문 설정 그대로 MNLI·SST-2 전체 데이터 파인튜닝 3회. 결과는 재현 트랙으로 표시해 본 실험 결과와 분리한다.
9. **대기열 실행기** — 본 실험 실행을 인프라 담당 한 사람이 한 번에 하나씩 순차 실행한다. 디버깅 실행은 대기열 밖에서 각자 돌리고 디버깅으로 기록된다.
10. **판정 모듈 (판정 seam)** — `결과 레코드 묶음 + 판정 규칙 문서 → 가설별 판정표`. 순수 함수. 디버깅 실행·재현 트랙 레코드는 판정에 넣지 않는다. 시드 평균·표준편차, 짝지은 McNemar, 길이 구간별 오차율, 최소 표본 기준, 무게중심, 전역 층 가중치 비율, 시드 일관성, F4 길이–가중치 순위 상관을 계산한다.
11. **보고 모듈** — 결과표(오차율 ± 표준편차, 학습 파라미터 수, 학습 시간), 학습 곡선, 층 가중치 그림, 길이 구간별 표, 시야 비율 표를 만든다.

### 데이터 형태 (계약)

- **실행 설정**: 데이터셋(MNLI/SST-2/IMDB) · 데이터 양 조건(전체/소량) · 결합 방식(B0/F1/F2/F3/F4/B0+, 재현 트랙만 논문 분류 헤드 `paper_head`) · 층 부분집합(전체/전역만/지역만, F2만) · 백본 조건(백본 고정/파인튜닝) · 입력 설정(IMDB만: L128/L512/Lfull) · 시드 · 학습률 후보 · 에폭 수 · 조기 종료 기준 · 실행 종류(본 실험/디버깅) · 트랙(본 실험/재현) · 고정 학습률과 그 학습률을 고른 시드(학습률 선택 실행에서 받은 값. 없으면 이 실행이 학습률을 고른다) · 재현 설정(재현 트랙만: 가중치 감쇠·warmup 비율·학습률 스케줄러).
- **결과 레코드**: 실행 설정 · 학습률 선택 결과(학습률을 고른 시드 포함) · 평가셋 오차율(MNLI는 matched/mismatched 각각) · 문서 ID별 예측·정답 · 학습 파라미터 수 · 학습 시간 · 튜닝 평가 시간 · 학습률 탐색 시간 · 학습 곡선 · 층 가중치(F2는 레코드 최상위, F4는 문서별 예측 항목 안) · 소량 표본 문서 ID · transformers 버전·어텐션 구현·컴파일 설정.
- **캐시 생성 설정**: 모델 · 버전 · 길이(입력 설정, 상한) · 자르기 방식.
- **판정 규칙 문서**: 판정 기준 · 최소 표본 기준 · 시드 일관성 기준값. 11/30 고정, 이후 변경하지 않는다.

### 실험 행렬 (ADR에서 정해진 범위)

| 데이터 | 백본 조건 | 데이터 양 | 입력 설정 | 결합 방식 | 쓰는 가설 |
|---|---|---|---|---|---|
| MNLI | 고정 | 전체 | — | B0, F1, F2, F3, F4, B0+ | H1, H4′ |
| MNLI | 고정 | 소량 | — | B0, F1, F2 (결정 안건 B) | H2 |
| MNLI | 파인튜닝 | 전체 | — | B0, 가장 좋은 결합 방식 | H3 |
| SST-2 | 고정 | 전체 | — | B0, F1, F2 (결정 안건 B) | H4(탐색) |
| IMDB | 고정 | 전체 | L128, L512, Lfull | B0, F1, F2 | H5a, H5b |
| IMDB | 고정 | 전체 | L128, L512, Lfull | F2 전역 층만 / 지역 층만 | H5c(탐색) |
| IMDB | 고정 | 전체 | Lfull | F4 | H5c(탐색) |
| MNLI, SST-2 | 재현 트랙 | 전체 | — | 논문 설정 × 3회 | 공개 수치 재현 |

### 그 밖의 결정 (근거)

- 백본은 ModernBERT-base 하나(ADR 0002). 선행연구와는 보고된 경향과의 정성 비교만 한다.
- transformers 버전, 어텐션 구현, 컴파일 설정을 각각 하나로 고정한다(ADR 0005).
- IMDB는 백본 고정만 하므로 입력 길이는 층 벡터 추출 단계에만 영향을 주고, 분류기 학습 배치는 세 입력 설정에서 같다(ADR 0004).
- B0+는 MNLI 본 실험에만 둔다(ADR 0008).
- 재현 트랙은 본 실험 B0 파인튜닝으로 대신하지 않는다(ADR 0004).

## 테스트 결정 (Testing Decisions)

### 좋은 테스트의 기준

- 바깥 행동만 검사한다. seam에 넣은 것과 나온 것만 보고, 내부 구현은 검사하지 않는다.
- 실행 seam과 판정 seam 테스트는 실제 GPU·실제 데이터 없이 돈다(가짜 층 벡터 공급원, 손으로 만든 결과 레코드). 실제 모델은 추출 확인 테스트에서만 쓴다.
- 테스트 하나가 ADR 규칙 하나를 드러내게 한다.

### Seam ① 실행 seam: `실행 설정 + 층 벡터 공급원 → 결과 레코드`

가짜 층 벡터 공급원으로 검사한다.

- 결합 방식별 학습 파라미터 수가 정의와 같고, B0+와 F4의 학습 파라미터 수가 맞춰져 있다.
- 한 층의 값 척도만 크게 바꿔도 층별 정규화 덕분에 F1의 결과가 바뀌지 않는다.
- F2에 전체 스케일 계수가 없다.
- 전역 층만 / 지역 층만 옵션에서 층 가중치가 각각 8개 / 14개이고 임베딩 벡터가 빠진다.
- 소량 조건에서 같은 시드의 모든 결합 방식이 같은 표본 문서 ID를 쓰고, 시드가 다르면 표본이 다르다. 표본은 클래스당 1,000건이다.
- 결합 방식이 달라도 학습률 후보 수·에폭 수·조기 종료 기준이 같다.
- 학습률은 튜닝 분할 결과로 고르며, 평가셋 라벨을 바꿔도 학습률 선택이 바뀌지 않는다.
- MNLI 결과 레코드에는 matched/mismatched 오차율이 각각 있다.
- 공급원의 생성 설정과 실행 설정이 다르면 오류가 난다.
- 결과 레코드에 학습 파라미터 수, 학습 시간, 학습 곡선, 문서별 예측, 실행 종류가 있다.

### Seam ② 판정 seam: `결과 레코드 묶음 + 판정 규칙 문서 → 가설별 판정표`

손으로 만든 결과 레코드로 검사한다.

- 차이 < 시드 간 표준편차이면 효과 없음.
- 차이가 표준편차보다 커도 McNemar가 유의하지 않으면 효과 없음.
- 둘 다 통과하면 지지.
- McNemar는 같은 문서끼리 짝지어 계산된다.
- 디버깅 실행·재현 트랙 레코드는 판정에 들어가지 않는다.
- 탐색적 가설(H4, H5c)에는 지지/효과 없음 판정이 붙지 않는다.
- 시드 일관성 기준에 못 미치면 층 가중치 해석이 보류된다.
- 무게중심·전역 층 가중치 비율이 손으로 계산한 값과 같다(예: 22층에 가중치가 모두 실리면 무게중심 22, 전역 층 가중치 비율 1).
- H5b 보고에 섞기 효과(F1 − B0)와 가중치 학습 효과(F2 − F1)가 나뉘어 나온다.

### Seam ③ 추출 확인 테스트 (실제 ModernBERT, 짧은 입력 몇 개)

고정한 버전에서 실행한다.

- 문서당 층 벡터가 23개이고, 마지막 층 벡터가 최종 정규화된 출력의 토큰 평균과 같다.
- **캐시 형태와 순서**: 캐시가 [문서 수, 23, 768]이고, 문서 ID·라벨 순서가 원본과 일치한다.
- **패딩 제외**: 평균 풀링에서 패딩이 제외된다. 같은 문서는 패딩 양이 달라도 층 벡터가 같다.
- **자르기 길이**: L128 = 앞 32 + 뒤 94, L512 = 앞 128 + 뒤 382, 특수 토큰 포함 128 / 512.
- **짧은 문서 동일성**: 512보다 짧은 문서는 L512와 Lfull 벡터가 같다.
- **생성 설정 기록**: 캐시 파일에 생성 설정(모델·버전·길이·자르기 방식)이 기록되고, 실행할 때 설정과 다르면 오류가 난다.

### 보조 단위 테스트

- 시야 비율: GLOSSARY 정의(앞뒤 64토큰씩, 자신 포함 129토큰)로 계산하면 길이 128 문서의 평균이 약 0.754로, ADR 0006의 "약 75%"와 맞는다. 129토큰 이하 문서는 1.0이다.
- 길이 구간 경계: 512는 ≤512, 513과 1,024는 512~1,024, 1,025는 1,024 초과에 들어간다.

### 선행 사례

새 저장소라 기존 테스트는 없다. 위 세 seam 테스트가 이후 테스트의 본보기가 된다.

### 11/30 판정 규칙 문서에 고정할 것 (ADR 0007)

> **결정 제안(T-07a, 2026-11-25, 고용민 작성 — 차가원 승인 전, `decision_rules.yaml`은 `status: draft`).** 아래 항목의 값은 `configs/decision_rules.yaml`에 채웠고 두 사람이 승인하면 11/30에 `locked`로 바꾼다. 승인 전에는 본 실험 판정이 시작되지 않는다(로더 `require_locked`). 근거와 값:
> - **H1·H2·H4′·H5a 대표 방식: F2 하나.** F2(학습된 전역 층 가중치)가 연구 질문의 본체이고 H5b도 F2로 판정하기 때문이다. 확증 비교가 B0 대 F2 하나라 **다중 비교 보정은 하지 않는다**(`multiple_comparison_correction: none`). F1·F3·F4는 보조 보고다. 확증 가설 간 보정은 하지 않고 ADR 0007의 우선순위로 다룬다.
> - **여러 시드 결합: `majority_of_seeds`, 유의수준 α = 0.05.** 절반을 넘는 시드가 유의해야 지지(5시드 3개, 3시드 2개). "차이 ≥ 시드 표준편차" 조건이 AND로 걸려 있어 α를 더 낮추지 않는다. 시드 간 p값에는 별도 보정을 하지 않으며, 보고서 한계 절에 적는다.
> - **최소 표본: 구간당 100건, 미달은 표에 남기고 `below_min_samples`로 표시해 해석 보류**(`flag_and_keep`). 오차율 10% 근처에서 n=100의 95% 신뢰구간이 약 ±6%p다. 값은 관례에서 나왔고 IMDB 구간별 문서 수 분포로 확인한다(평가 결과로 확인하지 않는다).
> - **시드: 핵심 5시드 `[0..4]`, 나머지·파인튜닝 3시드 `[0..2]`, 목록은 중첩.** 핵심 비교(5시드)는 `mnli_frozen_full`(H1·H4′)과 `imdb_frozen_length`(H5a·H5b)이고, 소량·파인튜닝(`finetune_num_seeds: 3`)·SST-2·ablation·IMDB F4는 3시드다. **H2·H3은 두 효과가 다른 시드 수로 돌아도 공통 시드(0~2)로 판정하고**(2개 미만이면 오류) 쓴 시드와 뺀 시드를 `details["seeds"]`·`details["excluded_seeds"]`에 남긴다. 시드 표준편차와 시드 결합(`majority_of_seeds`)도 이 공통 시드만으로 계산하므로 H3에서 백본 고정 5시드 중 2시드의 변동은 표준편차에 들어가지 않는다(한계 절에 적는다). 파인튜닝은 비싸므로 3시드로 두고, 시드 집합은 결과가 아니라 설정의 시드 목록으로만 정해져 사후 선택이 아니다. H1·H4′·H5a·H5b는 자기 실험의 시드 전체를 쓴다.
> - **파인튜닝용 "가장 좋은 결합 방식": 백본 고정 MNLI 전체의 학습률 선택 실행(시드 0)에서 선택된 학습률의 튜닝 분할 오차율이 가장 낮은 F1~F4**(B0·B0+ 제외, 동률이면 번호가 앞선 쪽, `lowest_tuning_error_among_f1_to_f4`). 평가셋 오차율을 쓰면 평가셋으로 고르는 셈이라 낙관적이 되어 튜닝 분할을 쓴다. 한 시드의 튜닝 점수라 잡음이 있다는 점은 한계 절에 적는다.
> - **임베딩 처리: 무게중심·전역 층 가중치 비율 모두 임베딩을 뺀다**(`include_embedding_in_cog: false`, `include_embedding_in_global_denom: false`). 임베딩은 층 번호가 없고 전역·지역에 속하지 않으므로 1~22층으로 재정규화해야 무게중심이 층 번호로 정의되고 전역 비율과 지역 비율의 합이 1이 된다.
> - **시드 일관성: 순위 상관 평균 ≥ 0.7, 무게중심 시드 표준편차 ≤ 2.0층.** 근거 문서가 없는 팀 판단값(관례값)이며, 본 실험 가중치를 본 뒤에는 바꾸지 않는다.

### 구현 단계에서 정할 것

- F4의 구체 형태(게이트 구조와 입력 벡터) → **결정(2026-11-24, T-05b PR #18, 차가원 리뷰 동의): 층별 정규화된 23개 층 벡터의 평균을 입력으로 받는 선형 게이트 `Linear(768 → 23)` → softmax 문서별 층 가중치 → 가중합 → 선형 분류기.** 게이트 weight·bias는 0으로 초기화해 학습 시작 시 F4 = F1이다(F2와 같은 출발점). 학습 파라미터는 MNLI 19,994개 / 2클래스 19,225개다(게이트 768×23+23 = 17,687 + 분류기). 근거: 모든 층 정보를 요약한 입력을 보고 층을 고르며, 입력이 768차원이라 ADR 0008의 B0+ 은닉 크기(26 / 25)와 파라미터 수가 맞는다. 대안(마지막 층 벡터만 입력)은 파라미터 수가 같지만 한 층만 보고 층을 고르므로 택하지 않았다. 입력이 층별 정규화 뒤 벡터라 문서별 층 가중치도 층의 값 척도를 따라가지 않는다.
- F2·F4 층 가중치의 정규화 방식(예: softmax 여부) → **F2 결정(2026-11-19, T-05a, 차가원 PR 승인으로 확정): softmax.** 층마다 학습 로짓 하나를 두고 softmax로 가중치를 만든다(양수, 합 1). 근거: 가중치 합이 1이라 전체 스케일 계수 γ를 두지 않는 ADR 0005와 맞고, 무게중심·전역 층 가중치 비율이 그대로 정의된다. 로짓은 0으로 초기화해 학습 시작 시 F2 = F1이다. **F4 결정(2026-11-24, T-05b PR #18, 차가원 리뷰 동의): 같은 softmax**를 게이트 출력 23개 로짓에 적용한다(문서마다 양수·합 1). 이로써 문서별 무게중심·전역 층 가중치 비율도 F2와 같은 식으로 정의된다.
- 토큰 평균에 특수 토큰을 포함할지 → **결정(2026-11-18, PR #8 리뷰 고용민·차가원 합의, T-04b PR #13에서 기록): 포함한다.** `[CLS]`·`[SEP]`도 패딩 제외 토큰 평균에 들어간다(`configs/week1_env.yaml` `include_special_tokens_in_pool: true`).
- 학습률 후보 3개의 값, 에폭 수, 조기 종료 기준, 배치 크기, 파인튜닝 조건의 학습률 범위 → **학습률 후보 결정 제안(2026-11-25, 결정 안건 A, 차가원 채택 — 고용민 PR 리뷰 후 확정)**: 백본 고정 `lr_candidates` = 1e-4, 1e-3, 1e-2(층별 정규화된 768차원 벡터 위의 선형·작은 헤드라 로그 간격 3개로 넓게 덮음, 모든 결합 방식 동일 — ADR 0007), 파인튜닝 `finetune_lr_candidates` = 2e-5, 5e-5, 8e-5(ModernBERT 논문 Table 6이 MNLI 5e-5·SST-2 8e-5를 고름, 그 주변). 고른 학습률이 후보의 양 끝에 자주 걸리면 범위가 틀렸다는 신호이므로 본 실험 전 debug 실행에서 확인한다. **에폭 수·조기 종료 기준 → 결정 제안(2026-11-26, T-08d 시간 측정 후 차가원 채택 — 고용민 PR 리뷰 후 확정)**: `epochs` = 40(상한), `early_stopping` = patience 3에폭. 상한은 시간을 줄이는 값이 아니라 조기 종료가 걸리지 않을 때의 안전장치다. 상한이 낮으면 천천히 수렴하는 결합 방식만 덜 학습된 채 끝나 H1 비교가 기울므로, 백본 고정 실행은 상한이 아니라 조기 종료로 멈춰야 한다. **판단 규칙**(결과를 보기 전에 정함): 최저 에폭이 상한 − patience보다 뒤에 있으면 상한에 잘린 실행이고, 상한은 실제 학습률 선택 과정에서 가장 늦게 멈춘 에폭 S보다 5에폭 이상 여유를 둔다(S ≤ 25 → 30, 25 < S ≤ 35 → 40). **근거**(metis debug, 시드 0, 후보 3개·patience 3·배치 32, `docs/03-plan.md` §8 2026-11-26): 상한 20으로 돌린 학습률 점검에서 B0+(1e-4 선택)만 최저 에폭이 20이라 잘렸고, 상한 40으로 다시 돌리면 26에폭(최저 23)에 조기 종료로 멈췄다(S = 26 → 40). 나머지 MNLI 전체 방식은 11–16에폭, MNLI 소량(B0·F1·F2)은 9–20에폭에 멈췄다. 처음 제안한 20은 학습률 1e-3 고정 측정만 보고 정한 값이라, 작은 학습률이 뽑힐 때의 느린 수렴을 반영하지 못했다. **파인튜닝 전용 에폭·배치는 두지 않는다**(백본 고정과 같은 `training_budget`, 아래 파인튜닝 학습 루프 항목). 파인튜닝은 스케줄러 없이 학습률이 고정이라 보통 2–3에폭에서 튜닝 오차가 다시 올라가 patience 3으로 5–6에폭쯤 멈출 것으로 본다(T-08f 예상 약 10시간 — 배치 32, 방식 2개 × 학습 5회, 에폭당 약 12분). 조기 종료가 한 번도 걸리지 않으면 상한 40에서 약 80시간이 최악이므로, T-08f 첫 학습률 후보의 학습 곡선을 보고 이상하면 대기열을 멈추고 재검토한다. **배치 크기 → 결정 제안(2026-11-26, 차가원·고용민 이슈 #32 합의 — PR 리뷰 후 확정): 32.** 파인튜닝은 배치마다 가장 긴 문서에 맞춰 패딩하므로 `--limit` 표본의 VRAM 실측은 전체 MNLI에서 긴 문서가 몰린 배치를 대표하지 못해, 배치 64는 측정해도 공용 32GB GPU에서 OOM 위험을 배제할 수 없다. 배치 32는 실측 13.3GB로 여유가 크고, 재현 트랙(배치 32)과 같은 기준이다(ModernBERT 논문은 배치 크기를 밝히지 않아, 32는 팀이 고른 관행 값이다). 배치 64의 백본 고정 25–35% 단축은 포기한다.
- 튜닝 분할을 나누는 방식(분할을 하나로 고정할지 등) → **결정 제안(T-06a, 고용민 PR 리뷰로 확정): 하나로 고정.** 튜닝 분할은 시드와 무관한 상수 시드(0)로 한 번만 뗀다(라벨 층화, 2026-11-18 결정). 학습률은 설정 조합(데이터셋·데이터 양·결합 방식·층 부분집합·백본 조건·입력 설정)마다 **선택 실행 하나**(첫 시드)에서 후보를 모두 학습해 튜닝 분할 오차율로 고르고, 나머지 시드는 그 학습률로 한 번씩만 학습한다. 재사용 실행의 결과 레코드는 학습률 선택 결과가 비어 있고 학습률 탐색 시간이 없으므로, 후속 단계(T-06b·T-07·T-09)는 같은 설정 조합에서 시드가 "학습률을 고른 시드"인 선택 실행 레코드를 찾아 참조한다. 학습 손실이나 튜닝 손실이 유한하지 않게 된 후보는 **발산**으로 보고 선택에서 뺀다(튜닝 점수는 무한대로 기록). 후보가 모두 발산하거나 고정 학습률로 학습하다 발산하면 실행은 오류로 끝난다. 근거: ADR 0007 "튜닝 분할에서 고른 학습률로 시드를 반복". 시드마다 학습률을 다시 고르면 시드 간 표준편차에 학습률 선택의 흔들림이 섞인다. 동률이면 튜닝 손실이 낮은 쪽, 그것도 같으면 후보 목록에서 앞선 쪽을 고른다.
- 조기 종료 기준의 대상 → **결정 제안(T-06a): 튜닝 분할 오차율.** 학습은 튜닝 분할을 뺀 학습셋 90%로 하고, 튜닝 분할 오차율이 가장 낮았던 에폭의 가중치로 되돌린다. 개선은 학습률 동률 규칙과 같게 (튜닝 오차율, 튜닝 손실) 순서로 비교한다. 오차율이 낮아지거나, 오차율이 같고 손실이 낮아질 때만 개선으로 센다(튜닝셋이 작은 IMDB·SST-2에서 오차율 동률이 잦기 때문, PR #15 리뷰). 조기 종료 기준(patience)은 1 이상이어야 한다. 선택 실행은 고른 학습률의 모델을 그대로 보고하며 다시 학습하지 않는다. 평가셋은 학습률 선택에도 조기 종료에도 쓰지 않는다.
- 소량 표본을 뽑는 범위(튜닝 분할 포함 여부)와 소량 조건의 학습률 선택에 쓸 튜닝 분할 → **결정 제안(T-06a): 튜닝 분할을 뺀 90%에서 클래스당 1,000건을 뽑고, 튜닝 분할은 전체 데이터 조건과 같은 것을 쓴다.** H2가 학습 데이터 양만 바꾸도록 하기 위해서다. 튜닝 분할이 소량이 아니라는 점은 보고서 한계 절에 적는다.
- MNLI 소량 조건과 SST-2에서 돌릴 결합 방식 목록 → **결정 제안(2026-11-25, 결정 안건 B, 차가원 채택 — 고용민 PR 리뷰 후 확정)**: `mnli_frozen_small` = B0, F1, F2 — H2는 소량·전체에서 B0 대 H1 대표 방식(F2)의 효과를 비교하므로 B0·F2가 필요하고, F1을 넣어 섞기 효과(F1−B0)도 같이 본다. `sst2_frozen_full` = B0, F1, F2 — H4(탐색적)는 F2 층 가중치를 MNLI와 비교하고 B0·F1은 오차율 기준선이다. 이 두 설정에서는 F3·F4·B0+를 제외한다. IMDB Lfull의 F4 등 다른 실험 셀은 실험 행렬을 따른다.
- 학습 시간 측정 범위(층 벡터 추출 시간 포함 여부) → **부분 결정 제안(T-06a): 결과 레코드의 학습 시간은 보고하는 모델의 학습 단계(순전파·역전파·optimizer)만 잰다**(학습률 탐색, 에폭마다 하는 튜닝 분할 평가, 층 벡터 추출은 뺀다). 선택 실행만 후보를 모두 학습하므로, 탐색 시간을 넣으면 그 시드만 튀어 학습 시간 표준편차가 왜곡된다. 튜닝 분할은 데이터 양과 무관하게 같으므로(MNLI 소량은 학습 3,000건에 튜닝 39,270건), 튜닝 평가 시간을 넣으면 전체/소량 학습 시간 비교가 왜곡된다(PR #15 리뷰). 튜닝 평가 시간과 학습률 탐색 시간(모든 후보의 학습 + 튜닝 평가)은 결과 레코드에 따로, 추출 시간은 캐시 `report.json`에 남는다. 보고 표에 추출 시간을 더할지(`extract_time_included_in_train_time`) → **결정 제안(2026-11-26, 차가원 채택 — 고용민 PR 리뷰 후 확정): 더하지 않는다(`false`).** 층 벡터 캐시 하나를 모든 결합 방식·시드가 공유하므로 추출 시간을 실행마다 더하면 같은 비용이 여러 번 세어지고 결합 방식 간 학습 시간 비교에 상수만 더해진다. 추출 시간은 캐시 `report.json` 값을 보고서에 따로 한 번 적는다.
- 학습 루프의 optimizer와 손실 → **구현 기본값(T-06a, PR #15·PR #18 확인): `torch.optim.AdamW`(가중치 감쇠 외 기본 설정), 손실은 cross-entropy.** 가중치 감쇠 0.01은 모양만이 아니라 **역할 기준**으로 적용한다: 표현·분류 변환용 2차원 이상 가중치 행렬(분류기 weight, B0+ MLP 은닉층 weight 등)에만 0.01을 걸고, bias와 **층 가중치를 만드는 파라미터(F2 `layer_logits`, F4 게이트 `weight`·`bias`)**에는 0을 쓴다(`fusion.no_weight_decay_parameters`). F2 로짓이나 F4 게이트 가중치에 감쇠를 걸면 초기에는 균일 가중치(F1), 학습 중 F4는 입력 의존 항이 눌려 정적 가중치(F2) 쪽으로 당겨져 F1·F2·F4 비교가 치우친다(PR #15·PR #18 리뷰). 대조군 B0+의 MLP 은닉층 가중치는 표현 변환 역할이라 0.01을 받는 반면 F4 게이트는 softmax 볼록결합 라우팅 역할이라 0을 받는 차이는 ADR 0008 형태 차이와 함께 한계로 남긴다. 같은 역할 규칙을 모든 결합 방식에 적용한다.
- 파인튜닝 조건에서 보고할 파라미터 수의 범위(백본 포함 여부) → **기록 방식 제안(T-06d, 승인 대기 — 고용민 PR 리뷰 후 확정, 범위 결정 아님): 결과 레코드의 `trainable_params`에는 실제로 학습한 파라미터 수(백본 포함, ModernBERT-base 약 1.49억 + 헤드)를 적는다.** 보고표에 어느 범위를 쓸지는 여전히 미정이다(T-09a). 같은 결합 방식의 백본 고정 레코드에 헤드만의 수가 있다.
- 파인튜닝 조건의 학습 루프 → **구현 기본값 제안(T-06d, 승인 대기 — 고용민 PR 리뷰 후 확정): 백본 고정과 같은 규칙.** AdamW, 가중치 감쇠 0.01은 2차원 이상 가중치에만(백본 포함, 단 층 가중치를 만드는 파라미터 — F2 logits, F4 게이트 — 의 감쇠 여부는 PR #18 리뷰 결론을 백본 고정과 똑같이 따른다), 학습률 하나를 백본과 헤드에 똑같이 적용, 학습률 스케줄러·warmup 없음, fp32(혼합 정밀도 없음). 학습률 선택(후보는 `finetune_lr_candidates` = 2e-5, 5e-5, 8e-5, 위 학습률 후보 항목)·조기 종료·튜닝 분할·학습 시간 측정 범위는 백본 고정과 같다. 학습률 후보 모델은 학습 직후 CPU로 옮기고 고른 모델만 장치로 되돌리며, 조기 종료용 최적 가중치 사본도 CPU에 둔다(파인튜닝 모델은 ModernBERT 전체라 GPU 메모리 보호). 층 벡터는 매 배치마다 추출기와 같은 규칙(패딩 제외 토큰 평균, 특수 토큰 포함, 23개)으로 계산하고, 학습률 후보·시드마다 사전학습 가중치에서 새로 시작한다. 에폭 수·배치 크기는 백본 고정과 같은 `training_budget` 값을 쓴다. 근거: ADR 0007 같은 튜닝 예산. GPU 실측(T-06d 디버깅 실행, T-08a)에서 학습이 너무 느리거나 불안정하면 bf16·warmup·파인튜닝 전용 에폭/배치를 11/30 전에 팀이 다시 정한다.
- B0+와 F4 파라미터 수의 허용 차이 → **결정(2026-11-24, T-05b PR #18, 차가원 리뷰 동의): 상대 차이 1% 이하**(|B0+ − F4| / F4 ≤ 0.01, `fusion.PARAM_MATCH_TOLERANCE`). B0+의 은닉 크기는 정수라 은닉이 1 늘 때마다 파라미터가 약 772개 뛰므로 정확히 같게 만들 수 없다. 현재 설계의 차이는 MNLI 81개(F4 19,994 vs B0+ 20,075, 0.41%), 2클래스 52개(19,225 vs 19,277, 0.27%)다. 이 검사는 F4 형태나 B0+ 은닉 크기가 한쪽만 바뀌는 실수를 잡는 안전장치다. B0+의 활성화 함수는 근거 문서에 없어 구현 기본값 ReLU로 두었다(은닉 크기와 파라미터 수에는 영향 없음).
- MNLI가 거절되어 AG News(4클래스)로 바꿀 경우의 B0+ 은닉 크기. ADR 0008은 MNLI 26 / 2클래스 25만 정했다
- 층 벡터 캐시 저장 정밀도. 참고: MNLI 학습셋 캐시는 float32로 약 28GB, float16으로 약 14GB다. → **결정(2026-11-18 PR #8 리뷰 합의 "float16 저장, 최대 절댓값 실측 후 확정", 2026-11-19 T-04b PR #13 실측으로 확정): float16.** 가장 짧은 입력까지 포함한 실측 최대 |값| 7,994로 float16 최대 65,504 대비 약 8.2배 여유, 반올림 상대 오차 ≤ 2^-11(`docs/measurements/float16_range_check.json`). 캐시 생성 때 배치마다 NaN·범위를 검사해 넘으면 그 분할을 남기지 않는다. 캐시는 저장 dtype 그대로 읽히고, 소비자(T-06a)가 미니배치마다 float32로 올린다.
- 재현 트랙의 논문 설정(ADR 0004, T-06e) → **논문 값(arXiv 2412.13663v2 부록 E.1·Table 6, ModernBERT-base, PDF 원문 확인): MNLI 학습률 5e-5·가중치 감쇠 5e-6·1 에폭, SST-2 학습률 8e-5·가중치 감쇠 1e-5·2 에폭.** 공개 점수(Table 5)는 GLUE dev 기준 MNLI 89.1·SST-2 96.0이고, 논문은 이 값들을 학습률·감쇠·에폭 탐색으로 골랐다. 결과 레코드의 결합 방식은 `paper_head`로 적는다(B0와 구별, GLOSSARY 재현 트랙). **논문에 없는 값 → 결정 제안(2026-11-25, 결정 안건 C, 차가원 채택 — 고용민 PR 리뷰 후 확정)**: **배치 크기 32**(GLUE 파인튜닝에서 널리 쓰는 값. 11/25 metis 점검 실행에서 MNLI 최대 GPU 메모리 13,442 MiB로 RTX 5090에 여유), **warmup 비율 0.06**(RoBERTa 계열 GLUE 파인튜닝 관례. warmup 없이 학습률 8e-5로 시작하면 초반이 불안정할 수 있음), **학습률 스케줄러 `linear`**(transformers 기본값), **시드 0·1·2**(본 실험 3시드와 같은 값, 시드 수 = `num_runs` 3은 코드가 강제) — `configs/experiment_matrix.yaml` `reproduction_track`에 반영. 넷 다 **논문 값이 아니라 우리가 고른 관행 값**이므로 보고서 한계 절에 적는다. **MNLI 공개 수치(89.1, 오차율 10.9%)와 비교할 우리 오차율은 matched 오차율**로 정한다(mismatched는 옆에 병기). 논문은 MNLI 숫자 하나만 적고 어느 쪽인지 밝히지 않았는데, GLUE dev 표는 보통 matched를 MNLI 대표로 쓴다. 재현 결과를 보기 전에 정한 값이다. 레코드에는 둘 다 있고 CLI는 둘 다 공개 수치 옆에 출력한다. **결정 제안(T-06e, 승인 대기 — 고용민 PR 리뷰 후 확정)**: (0) 분류 헤드는 transformers 5.23.0 `ModernBertForSequenceClassification` 기본값(토큰 평균 풀링 → Dense → GELU → LayerNorm → Linear)을 쓴다. 논문이 공개 코드의 헤드를 명시하지 않아 고정된 transformers 버전의 기본 헤드를 논문 헤드로 본다는 해석이다. (1) 학습은 튜닝 분할을 떼지 않고 학습셋 전체로 하고, Table 6 에폭을 고정으로 다 돈 뒤 **마지막 모델**을 평가한다. 논문은 조기 종료를 썼다고만 하고 기준을 밝히지 않았는데, 평가셋(dev)으로 에폭을 고르면 평가셋으로 모델을 고르는 셈이라 낙관적이 된다. 에폭마다 dev 오차율은 학습 곡선에만 남긴다. (2) optimizer는 AdamW, 감쇠는 논문 값을 bias·LayerNorm 가중치를 뺀 파라미터에 건다(Hugging Face 관례, 논문에 명시 없음). (3) 재현 실행도 공용 GPU를 오래 쓰므로 본 실험 대기열과 같은 잠금(ADR 0009)을 잡는다. 보고서 한계 절에 미정 값과 조기 종료 차이를 적는다.
- 가설별 판정·분석의 구체 연산(T-07c) → **결정 제안(T-07c, 승인 대기 — 차가원 PR 리뷰 후 확정, 11/30 T-07a에서 확정 또는 교체)**: (1) **H3·H2·H5b는 '효과 A가 효과 B보다 크다'를 묻는다.** 효과 = 시드 평균 오차율 개선(기준 − 개선). 지지는 효과 차이가 두 효과의 시드 표준편차 중 큰 값 이상이고, 문서별 이득(+1: 개선 쪽만 맞힘, −1: 기준 쪽만 맞힘, 0)이 두 효과에서 다른 문서에 대한 양측 정확 부호 검정(McNemar의 확장)이 시드별로 계산돼 `multi_seed_mcnemar_aggregation`으로 결합한 값이 알파 미만일 때다. 시드는 자기 효과 A가 B보다 크고, **A 쪽으로 이득이 더 큰 문서 수가 반대 방향 문서 수보다 많을 때만** 센다(문서별 이득 차는 −2~+2라 순 오차율 차이와 문서 수 방향이 어긋날 수 있고, 어긋나면 그 시드는 지지 근거가 아니다 — 2차 교차검증 반영). `details`에는 시드별 부호 검정 p·양쪽 문서 수(`per_seed_documents_ahead`)와 각 효과의 두 팔 오차율 평균(`mean_error`, H3에서는 백본 고정·파인튜닝의 B0·결합 방식 오차율 — 파인튜닝 대비 향상폭의 근거)을 둔다. 근거: '유의한 결과'와 '유의하지 않은 결과'를 따로 내 비교하면 그 차이 자체가 유의한지 검정하지 못한다. H2는 소량 vs 전체(B0 대비 대표 방식), H3은 백본 고정 vs 파인튜닝(파인튜닝 레코드의 B0가 아닌 방식 하나가 후보, 둘 이상이면 오류), H5b는 L512 → Lfull로 긴 입력을 쓸 때 줄어든 오차율이 F2에서 B0보다 큰지다. (2) **H2·H4′의 대표 방식은 `h1_target_fusion_rule`을 재사용한다**(새 규칙 필드 없음). H4′는 같은 레코드의 mismatched 문서만으로 H1 비교를 다시 한다. H5a는 `h5a_target_fusion_rule` 방식의 L512 vs Lfull을 같은 B0-vs-후보 판정으로 본다. (3) **길이 구간은 판정이 아니라 보고다.** H5a·H5b는 IMDB 평가셋 전체로 판정 하나를 내고, 구간별 문서 수·오차율은 `length_bucket_analysis`에 두며 `below_min_samples`는 `min_bucket_samples`가 확정되기 전에는 `None`이다. ≤512 구간은 L512와 Lfull의 문서 ID·토큰 길이가 같은지만 점검하고(다르면 오류) 오차율 차이는 보고만 한다(두 설정의 분류기는 서로 다른 학습 입력으로 학습되므로 예측이 같을 필요가 없고, 임계값을 만들면 값을 지어내게 된다). (4) **무게중심·전역 비율의 임베딩 처리는 규칙값을 그대로 따른다.** `False`면 임베딩 가중치를 빼고 1~22층으로 재정규화, `True`면 임베딩을 위치 0으로 센다(전역·지역 부분집합은 임베딩이 없어 무관). 값이 `None`이면 오류다. (5) **시드 일관성**: 시드 쌍 스피어만 순위 상관의 평균이 `seed_rank_corr_min` 이상이고 무게중심의 시드 표준편차가 `cog_seed_std_max` 이하일 때만 해석한다. 상관이 정의되지 않으면(가중치가 모두 같음) 미달로 본다. 미달이면 `layer_weight_analysis[셀]['interpretation'] = 해석 보류`다. (6) **H4·H5c(탐색)는 판정을 붙이지 않고** `details`에 F2 무게중심·전역 비율·SST-2 오차율 비교 수치·전역/지역 ablation 오차율·F4 길이–전역 비율 순위 상관(전체·라벨별)을 담는다. 의존하는 층 가중치가 시드 일관성에 미달이면 행의 판정은 그대로 탐색적이고 `details['layer_weight_interpretation']`만 해석 보류가 된다. (7) **보조 분석은 판정을 막지 않는다.** 층 가중치 요약·F4 상관에 필요한 규칙값이 TBD이면 그 셀은 오류 대신 `unavailable`(사유)로 남고, 시드가 하나뿐인 F2 셀은 일관성을 보일 수 없으므로 해석 보류다. 공개 함수 `compute_center_of_gravity`·`compute_global_layer_weight_ratio`는 임베딩 규칙값으로 `None`을 받으면 오류다. H4의 SST-2 오차율 비교는 판정을 붙이지 않으므로 알파 없이 계산하고, `h1_target_fusion_rule`·`multi_seed_mcnemar_aggregation`이 TBD이면 `unavailable`로 남는다. ≤512 점검은 L512·Lfull 시드가 짝지어지지 않으면 그 방식만 `unavailable`이고(해당 시드가 필요한 확증 가설은 자기 쪽에서 오류를 낸다), 짧은 문서의 토큰 길이가 없으면 오류다. F4 길이 상관은 IMDB **Lfull** F4만 대상이며, H5b의 F1 분해는 F1이 없거나 시드가 다르면 `decomposition_skipped`로 건너뛴다(F2 판정은 유지). `long_input_gain`의 키는 GLOSSARY의 섞기 효과·가중치 학습 효과와 다른 양(이득의 차이)이라 `mixing_gain_difference`·`weight_learning_gain_difference`로 이름 붙였다. **남은 위험**: H2·H3은 비교하는 두 효과의 시드 집합이 같아야 한다. 소량 3시드 vs 전체 5시드(`secondary_num_seeds` vs `core_num_seeds`)나 파인튜닝 시드가 백본 고정과 다르면(`finetune_num_seeds` 미정) 시드 집합 불일치 오류가 나므로 T-07a에서 시드 값을 맞추거나 짝짓기 방식을 정해야 한다. 다중 비교 보정은 아직 판정에 반영되지 않았다.

## 추가 메모 (Further Notes)

- **일정 기준점**: 1주차 확인(위 목록) → 11/30 판정 규칙 문서 고정 → 본 실험 → 12/14 최종 발표(보고서 4~6쪽, 코드, 발표).
- **우선순위**: 일정이 밀리면 MNLI > SST-2 > IMDB(ADR 0003). 1~4순위 가설(H1 > H3 > H2 > H4′)이 MNLI 하나로 판정되므로 IMDB가 늦어져도 핵심 결론은 지켜진다(ADR 0007).
- **지표**: 결과 보고와 판정은 오차율(낮을수록 좋음)로 통일한다(PDF, GLOSSARY). 논문 공개 수치처럼 정확도로 된 값은 오차율을 함께 적는다.
- **ADR 간 표현 불일치**: ADR 0003은 "SST-2는 층 가중치(무게중심)로 판정"한다고 적었지만, ADR 0007은 H4를 탐색적 가설로 두었고 GLOSSARY는 탐색적 가설을 "판정하지 않고 경향만 보고"한다고 정의한다. 이 명세는 ADR 0007·GLOSSARY를 따랐다. ADR 0003 문구 정리가 필요하다.
- **보고서 한계 절 후보**: B0+는 파라미터 수만 같고 형태가 다름(ADR 0008), 전역/지역 ablation의 층 수 차이 가정과 "출력의 쓸모" 해석(ADR 0006), F4는 "게이트가 길이에 반응한다"까지만 주장(ADR 0006), 선행연구 비교는 정성 비교(ADR 0002), 시드 표준편차는 평가셋 흔들림을 반영하지 못해 McNemar를 더함(ADR 0007).
